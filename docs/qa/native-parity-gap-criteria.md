- **侧栏页面的四角曲线族为圆弧近似。** zen `App/Workspace/SidebarSurfaceDecoration.swift:64-66` 用 SwiftUI `UnevenRoundedRectangle(style: .continuous)` 画四个角的圆角；UIKit 没有 CGPath 版的连续曲率，原生用**同一半径的普通圆弧**（`WorkspaceSidebar/SidebarSurfaceDecoration.swift` 的 `SurfaceCornerRadii.path`）。半径逐字取自 zen，差的是曲率形状本身——同一半径下四角会比连续曲率看起来更「方圆」，这是肉眼可辨的一处，不是「画得差不多」。层上要连续曲率的地方仍走 `cornerCurve = .continuous`。

## G4 · flat 平铺布局跟随（Mason）★ 唯一未确认「用户会不会用」的一条

RN 基准：`Chat.tsx:205-206,264-271` + `items.tsx:266-268,303-313`。

**这条不能只看「变宽了没有」。** RN 的 flat 有三个同时发生的现象，缺一个都算没做全：

1. **Bot 回复去掉气泡**：`items.tsx:303-313` 用 `alignSelf: 'stretch'` + `bg={p.main}`（页面底色），文字直接铺在背景上，没有圆角气泡面；
2. **宽度拉满整列**（对比气泡布局的 93% 上限）；
3. **群聊里成员头像列消失**：`items.tsx:268` 是 `inRoom && !flat`——头像 22pt 圆、彩色名字、Admin 徽标、时间那一整行都不画，只剩一行灰色小名字（`:301`）。

### 怎么在真机上造出来（Warden 点名要写清）

- [ ] **电脑端设**：DS Bot → 设置 → **消息布局** → 点 **「平铺」**（旁边是「气泡」）。选平铺后下面会多出「正文宽度」滑杆——**这个滑杆手机端不读**（RN `Chat.tsx:205-206` 只取 `layout` 和 `width`，且 `narrow = chatWidth < 520` 时连 `width` 也忽略），iPhone 上拨它不会变，别据此判失败。
- [ ] **手机端取到新值**：保持前台停在会话里，切一次对话再切回（触发一次 state 刷新），或等 ≤15 秒兜底轮询。
- [ ] **兜底**：若仍不变，杀进程重开——冷启动必然重拉 state，此时还不生效就是真没跟。

### 判定

- [ ] **算做了（1:1 会话）**：Bot 回复**没有气泡底和圆角**，文字铺在页面底色上、宽度到整列；用户消息仍是气泡（RN 只对 Bot/群员行做 flat）
- [ ] **算做了（群会话）**：成员头像、彩色名字、Admin 徽标**都不再出现**，只剩灰色小名字 + 正文
- [ ] **算做了（切回）**：电脑改回「气泡」→ 手机刷新后气泡、93% 宽、群头像列全部恢复，不需要重进会话
- [ ] **算没做**：完全无变化（现状：恒气泡布局）
- [ ] **部分实现，也记没过**：只有宽度变了、气泡还在；或气泡没了但仍留 93% 窄列；或群头像列还在
- [ ] **不要误判**：flat 只影响 Bot 与群员行，用户自己的气泡在 flat 下仍是气泡——这是 RN 的行为，不是缺失

- [ ] **算没做**：未选模型时毫无提示（现状）

### 已修的数据语义缺陷（`63ef6ba`，做模型功能前先读这一行）

编辑页的模型按钮由团队默认值预填，而原生的 Save 是延迟保存——**按一次 Save 就会把那个默认 ref 写进 `bot.model`**，用户什么都没选，数据里却记成选过。RN 只在 `onPick` 时保存（`model-menu.tsx:227`），预填值纯显示。现已改成只有本页真选过才进 patch。做模型单显示名、模型切换、用量统计这类功能时，别再把「按钮上显示的」当成「Bot 的」——两者不等价。

### 同一条线上的已知差异，本轮不做

无模型时触发器文案：RN 写「Choose a model」（`model-menu.tsx:216`，`modelOf` 取 `bot.model ?? bot.appliedModel`），原生把团队默认 ref 预填进按钮（`BotEditorViewController` 的 `model` 初值）。这与「模型单显示名」是同一条线的两半，一起做——**但它不影响 G6 的判定**：提示的显示条件仍按 RN 原文，只看 Bot 自己有没有 `model` / `appliedModel`。

## 已知差异（不进勾选，销账时照抄一句）

这一节记的是「我们知道和参考实现不一样，并且不改」的地方。不是缺口，也不是待办。

- **iOS 17–25 的顶栏渐隐是「模糊 + 18% 页面底色」的近似，不是纯色层。** 依据是用户给的参照图：内容在顶部逐渐模糊淡出，没有纯色硬边。做法是 `UIVisualEffectView(.systemUltraThinMaterial)` 加一层 `palette.main` alpha 0.18，两者共用一条 alpha 蒙版：顶段完全不透明、最后 24pt 降到 0、斜坡夹在高度 40% 以内（`ChatHeaderViews.swift` 的 `FadeOverlayView`，测试 `FadeOverlayTests`）。副产物是它比纯色层贵一次离屏模糊；像素结果与参照图的观感一致，但没有逐像素比对。
- **iOS 26 起顶栏边缘交给系统：`UIScrollEdgeEffect(.soft)`；17–25 用自绘模糊渐隐兜底。** 官方 API（`UIScrollView.topEdgeEffect`，iOS 26.0+）的三个 style 里 `.hard` 是「硬截止 + 分割线」——正是被否掉的那版；`.soft` 才是内容在顶栏下逐渐模糊的那张图。做法：`ChatViewController` 在装列表时调 `ChatTopEdgeEffect.apply(to:fallback:)`（`ChatTopEdgeEffect.swift`），26 上设 `.soft` 并把 `FadeOverlayView` 隐藏（不删，17–25 仍靠它）；测试 `ChatTopEdgeEffectTests`。**这是本项目第二次自造轮子被官方 API 取代**，第一次是 `cornerConfiguration`。尚未在真机核对系统的模糊带高度是否正好盖住自绘顶栏（列表顶边贴在屏幕顶、顶栏是自绘玻璃，不在导航栏位），出包后看图再定。
- **侧栏 rail 的按压动画曲线为近似。** zen `App/Workspace/SidebarRailView.swift:178` 是 SwiftUI `.spring(duration: 0.28, bounce: 0.3)`；UIKit 没有 bounce 这个参数，原生取同 0.28s 的 `usingSpringWithDamping: 0.7`（`WorkspaceSidebar/SidebarRailView.swift`，注释里也写了）。时长与触发时机一致，曲线是最近的近似，不是等价替换；Reduce Motion 下两边都不缩放。

### 未覆盖的判据

这里记的是「有判据、但自动化测试没有直接覆盖」的地方。列为已知缺口，不当作已验。

- **侧栏手势的触摸级准入未直接覆盖。** `WorkspaceSidebarInteraction.swift:196-235` 的 `shouldReceive` 决定一次触摸落进哪条 rail 条、`|x| > |y| * 1.1` 与「触摸点必须在锚点内」这几条判据；它需要 `UITouch`，而 `UITouch` 在 UIKit 之外造不出来。现有测试覆盖的是识别器挂载（root view / window）、`detach()`、方向翻转、以及 settlement 期间全拒（`native/Tests/TransportTests/SidebarInteractionTests.swift`）。不加 DEBUG 注入点（等于给 zen 的函数开洞），也不上 XCUITest（CI 上的另一个不稳定源）。

# 重连与断线的真机验证

> 这版同时改了网络层和玻璃 UI，所以断网这次单独验。
> 三组场景全过，才算这一块验完；每组都要记时间，感性描述（「好像挺快」）不算证据。
> 步骤按 `mobile/src/team/link.ts`、`mobile/src/net/supervised.ts`、`link/src/supervisor.ts` 的实现写，改动后要跟着改。

## 0. 前置条件

- 一台真机（任一机型），已配对好，聊天页里**有历史消息**（横幅只在 `team !== null && !online` 时出现，没加载过 team 就看不到横幅）
- 服务端跑在电脑上，手机与电脑同一局域网；或走远程 relay，两样都测一遍更稳
- 关闭自动锁屏（设置 → 显示与亮度 → 自动锁定 → 永不），否则 App 进后台，`setTimeout` 冻结，计时全乱
- 准备秒表 / 另一台手机录像（默认从「断网那一刻」记 0 秒）
- 知道在哪看电脑端状态：设置 → 电脑 → 那一行「已连接 / 连接中 / 未连接」

## 1. 这版的重连逻辑（判定全部从这里推）

- 重连只有一个入口：`LinkSupervisor`（`link/src/supervisor.ts`）。单飞，同一时刻只有一次尝试
- 退避：**1s 起、每轮 ×2、±20% 抖动、封顶 60s**；链路稳定 10s 以上才把退避重置回 1s（握手刚成就断的不算稳定，否则会变成连接风暴）
- `link.ts` 数**连续失败次数**，满 7 次（`DISCONNECTED_AT`）把横幅从「正在重新连接…」切成「未连接」+「**重试**」。7 次大约是断网后 **63 秒**（1+2+4+8+16+32），抖动下 50–76 秒；每次尝试本身还要耗时，实测可能更晚
- 点「重试」= `setError(null)` + `supervisor.reconnect()`，作用是**打断当前的等待、立刻再试一次**；它不是唯一入口，也不是唯一能恢复的方式（见第 5 节）
- 回前台只做 `client.probe()` + 补一次 `poll()`，**不是重连入口**；真正的重连一直由 supervisor 那圈 while 在跑
- 静默死链（Wi-Fi 断了但 socket 没报错）靠心跳发现：静默 15s 发 probe，10s 无回应再发一次，再 10s 无回应才判死 —— **最坏约 35 秒**才知道自己断了

## 2. 场景一：短暂断网（约 10 秒）

**怎么做**：停在聊天页 → 关 Wi-Fi（或开飞行模式）→ 数 10 秒 → 打开 → 不动手机，等 30 秒。

**看什么**：

1. 断网后横幅多久出现（顶部玻璃胶囊，转圈 +「正在重新连接…」）
2. 恢复网络后横幅多久消失
3. 立刻发一条消息，看能不能发出、几秒到
4. 全程有没有出现「未连接」

**判过**：

- 横幅出现（关 Wi-Fi 通常 1–2 秒内；开飞行模式若 socket 没报错，可能要等到心跳判死，最多约 35 秒——这个区别要记下来）
- 恢复后 20 秒内横幅消失，回到可收发
- 全程**不出现**「未连接」，也不出现「重试」按钮

**判失败**：

- 横幅一直不出现，但消息发不出去（说明断链没被感知，UI 在骗人）
- 恢复后横幅超过 30 秒还在（退避已经回到 1–8 秒档，这么久说明 supervisor 卡了）
- 10 秒的断网出现「未连接」——那是计数逻辑坏了，不该这么快

**失败先记这两条**：

1. 秒表时间线：断网 0s / 横幅出现 __s / 恢复 __s / 横幅消失 __s（没消失就写「没消失」）
2. 断网期间发的那条消息的下场：气泡在不在、旁边有没有红字、恢复后有没有补发、要不要重发

## 3. 场景二：长时间断网（约 90 秒）

**怎么做**：停在聊天页 → 断网 → 等 90 秒（期间盯横幅）→ 恢复网络 → **先什么都别点，等满 90 秒** → 如果还在「未连接」，点「重试」→ 再等 10 秒。

**看什么**：

1. 第 60 秒左右横幅是否切成「未连接」+「重试」
2. 恢复网络后**不点任何东西**，横幅多久自己消失
3. 点「重试」之后，多久回到在线
4. 设置 → 电脑 那一行在此期间分别显示什么（已连接 / 连接中 / 未连接）

**判过**：

- 断网 50–90 秒之间切到「未连接」，且「重试」可点、点了有反应
- 恢复网络后**最迟 72 秒**（60s 档 + 20% 抖动）内自己接回，横幅消失、消息能发 —— 这一步是自动的，不许靠点重试才算过
- 点「重试」的额外价值是**立刻**：网络已恢复时点它，5 秒内回到在线

**判失败**：

- 90 秒都没出现「未连接」（计数没走，或者被别的错误重置了）
- 恢复网络后超过 72 秒仍未接回，点「重试」也没用（这才是真的卡死，通常是 supervisor 停了或 `running` 丢了）
- 点「重试」后界面没有任何变化（按钮接到了空函数，或 supervisor 已经不在）

**失败先记这两条**：

1. 时间线：断网 0s / 切「未连接」__s / 恢复 __s / 自动接回 __s 或「没接回」/ 点重试 __s
2. 「重试」点下去之后发生的**第一件事**：横幅变回「正在重新连接…」？直接消失？还是毫无反应？以及设置 → 电脑 那行的文字

## 4. 场景三：电脑端断开 / 重启

**怎么做**：手机停在聊天页 → 在电脑上直接结束 DS Bot 进程（不是关终端窗口，要真的结束）→ 等 30 秒 → 重新启动 DS Bot → 不动手机，等 90 秒。再用「重启电脑」重复一次。

**看什么**：

1. 电脑停掉后，手机多久进重连；横幅是哪个状态
2. 电脑起来后，手机是否**自己**接回（不需要点重试、不需要切后台）
3. 接回后发一条消息，是否立刻能通
4. 设置 → 电脑 里的设备指纹有没有变（重装、换数据目录会变）

**判过**：

- 电脑停掉后手机进入重连（收到 close 时几乎是立刻；静默断最坏约 35 秒）
- 电脑起来后 90 秒内自动接回，无需操作
- 接回后消息立刻能发，历史消息不丢

**判失败**：

- 电脑起来后手机一直「未连接」，点重试也接不回（多半是 hostDeviceId 或配对状态变了，要重新扫码）
- 接回了但发消息失败、状态不刷新（链路起来但握手没过，见第 6 节）
- 需要杀 App 重开才恢复（说明是 supervisor 停了，不是网络问题）

**失败先记这两条**：

1. 电脑端终端最后 10 行（停掉前有没有报错、重启后有没有正常监听）
2. 手机端：横幅状态变化的时间点 + 设置 → 电脑 那行的设备指纹，前后是不是同一个

## 5. 别当 bug 的三件事（这版就是这样实现的）

1. **恢复网络后不是立刻接回，最长要等一个退避档**：第 7 次失败后 supervisor 仍在跑，档位已经到 60s（±20%），所以恢复后最多约 72 秒才自己连上。想快就点「重试」，它是「打断等待」，不是「唯一入口」。
2. **断网状态下点「重试」，会立刻又变回「未连接」**：`failures` 只在成功连上时清零，点重试不清零，所以下一次失败马上就是第 8 次，横幅秒回判定态。这是当前实现，记成观察项，不要记成阻断。
3. **进后台再回来不会立刻重连**：回前台只 probe + poll，计时器在后台是冻结的，所以「切出去 2 分钟再回来」不能用来验证退避时间，只能用来验证回前台能不能恢复。

## 6. 回归提醒：`linked` 和 `online` 是两回事

这版同时改了网络层与 UI。看到「消息发不出去但没有报错」，先分清这两个状态：

- `linked`：加密链路起来了（握手前的形态），`clientRef` 有值，能发 RPC
- `online`：hello 通过、电脑端版本对得上（`api !== null`），真正可以收发

两者由 `link.ts` 分开维护：`onStatus('online')` 一起置真；`onOpen` 里先 `setLinked(true)`，hello 失败再把 `linked` 打回 false 并给「电脑端 DS Bot 版本太旧」的错误；`onClose` 两个都置假。

所以真机上：

- **横幅在（`team !== null && !online`），但能发消息** → 是握手没过或状态没刷新，不是网络断
- **横幅不在，但发消息抛错** → 看报错文案：`还没有连上电脑` 是 `linked=false` 的兜底；`电脑没有连上 Server` / `连不上 Server` 是电脑端或 relay 的问题，不是手机
- **两个都没有，就是发不出去** → 先把设置 → 电脑 那行状态和横幅文案一起记下来，这比「发不出去」四个字值钱
